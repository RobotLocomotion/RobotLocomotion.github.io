    Drake v1.58.0

    Back to Release Notes

    Announcements

    • Drake now supports Xcode 27 (#25067).
    • The minimum supported macOS is now Tahoe (26) (#24988).
    • Keying an STL container (e.g., map, set, unordered_set, unordered_map) on drake::symbolic::Expression or drake::symbolic::Variable now requires additional syntax (#25014).
      • When using an ordered container (e.g., map, set), you must supply Expression::CompareLess (or Variable::CompareLess) as the Compare template argument.
      • When using an unordered container (e.g., unordered_map, unordered_set), you must supply Expression::CompareEqualTo (or Variable::CompareEqualTo) as the KeyEqual template argument.
      • The prior spelling (leaving the template argument at its default value) will continue to work during the 3-month deprecation period, but after that will fail to compile. (When using Xcode 27, no deprecation period is possible so it will break immediately without the change.)
      • Background: Newer libc++ introduced a map and set lookup optimization that requires std::less specializations to be equivalent to operator<. Any other behavior is non-conforming. For more context on the change, see the discussion on the LLVM issues #178847 and #179319. For Expression and Variable, their operator<s are used for logical comparison while their std::less specializations are used for structural comparison (and ditto for std::equal_to vs. operator==) so we must stop using the std::less specialization for containers and spell out the CompareLess functor instead.
